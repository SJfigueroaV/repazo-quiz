2.1 La lista que crece

Un ArrayList es una colección que no tiene tamaño fijo: crece cuando agregas y se compacta cuando eliminas. Vive en el paquete java.util, así que toca importarlo.

Compras.java
import java.util.ArrayList;

ArrayList<String> compras = new ArrayList<>();
System.out.println("Al crearla: " + compras.size() + " elementos");

compras.add("pan");
compras.add("leche");
compras.add("café");

System.out.println("Ahora: " + compras.size() + " elementos");
System.out.println("El primero: " + compras.get(0));
System.out.println("La lista entera: " + compras);

compras.remove("leche");
System.out.println("Sin la leche: " + compras);
System.out.println("¿Queda café? " + compras.contains("café"));

salida

Al crearla: 0 elementos Ahora: 3 elementos El primero: pan La lista entera: [pan, leche, café] Sin la leche: [pan, café] ¿Queda café? true

Lo primero que salta a la vista: no hay corchetes por ninguna parte. Donde el arreglo usaba sintaxis del lenguaje (arr[0] = x), la lista usa métodos (lista.add(x)). Y println de una lista imprime su contenido, que es mucho más cómodo que un arreglo (un arreglo imprime algo como [Ljava.lang.String;@2f92e0f4).

Arreglo (String[])Lista (ArrayList<String>)
Tamaño fijo, decidido al crearloTamaño variable, crece sola
arr[0] = "pan";lista.add("pan");

Recorrer una lista se parece a recorrer un arreglo. Con índice, cuando necesitas saber la posición:

for (int i = 0; i < compras.size(); i++) {
    System.out.println(i + ": " + compras.get(i));
}

O con for-each, cuando solo te importan los elementos. Es más corto y no puedes equivocarte con los índices, así que es el que se usa por defecto:

for (String producto : compras) {
    System.out.println(producto);
}

Tres formas de preguntar el tamaño

arreglo.length, texto.length(), lista.size(). Sí, es incómodo, y sí, lo vas a confundir varias veces. El compilador te avisa.

Pregunta rápida

Creas una lista vacía y agregas 3 elementos. ¿Qué devuelve lista.size() y cuál es el último índice válido para get?

Igual que en los arreglos: los índices empiezan en 0, así que con 3 elementos van de 0 a 2. lista.get(3) lanza IndexOutOfBoundsException.

2.2 Genéricos: qué cabe en la lista

En esta sección

  • Entiendes qué significan los diamantes <> y qué te dan a cambio.
  • Sabes qué escribir cuando quieres una lista de números.

Al declarar la lista le dices entre diamantes qué tipo de objeto puede entrar. Eso son los genéricos. Antes de Java 5 las colecciones guardaban Object, o sea cualquier cosa, y al sacar un elemento tocaba convertirlo a mano con un casting que podía explotar en tiempo de ejecución. Hoy el compilador te protege:

ArrayList<Producto> catalogo = new ArrayList<>();

catalogo.add(new Producto("P01", "Teclado", 150000.0));   // bien
catalogo.add("un texto cualquiera");                       // ERROR DE COMPILACIÓN

Ese error es una buena noticia: falla al compilar, en tu máquina, y no a media noche en producción. Fíjate también en el new ArrayList<>() del lado derecho: desde Java 7 no hay que repetir el tipo, el compilador lo deduce. Ese <> vacío se llama operador diamante.

Los genéricos no aceptan primitivos

ArrayList<int> no compila. Para guardar números hay que usar las clases envolventes: ArrayList<Integer>, ArrayList<Double>, ArrayList<Character>, ArrayList<Boolean>.

En la práctica casi no se nota, porque Java convierte solo entre int e Integer (eso se llama autoboxing):

ArrayList<Integer> numeros = new ArrayList<>();

numeros.add(5);                 // guardas un int, Java lo envuelve en un Integer
int primero = numeros.get(0);   // sacas un Integer, Java lo desenvuelve a int

for (int numero : numeros) {    // incluso aquí puedes usar int
    System.out.println(numero);
}

Pregunta rápida

¿Cuál de estas declaraciones compila?

Solo la segunda. double es un primitivo y no cabe entre diamantes; su clase envolvente es Double, con mayúscula. La tercera además tiene los tipos descuadrados entre el lado izquierdo y el derecho.

Hay un detalle que muerde a todo el mundo una vez. Fíjate en los dos remove: uno recibe un int (posición) y el otro un objeto (contenido). Con una lista de Integer, las dos versiones se parecen peligrosamente:

Trampa.java
ArrayList<Integer> numeros = new ArrayList<>();
numeros.add(1);
numeros.add(2);
numeros.add(3);

numeros.remove(1);                    // ¿borra el número 1... o la posición 1?
numeros.remove(Integer.valueOf(1));   // esta sí borra el número 1

salida (cada remove sobre una copia de la lista original)

Lista: [1, 2, 3] remove(1) borra la POSICIÓN 1: [1, 3] remove(Integer.valueOf(1)) borra el VALOR 1: [2, 3]

Java elige el método por el tipo del argumento: remove(1) ve un int y borra la posición. Para borrar por valor hay que pasarle un objeto Integer, con Integer.valueOf(1). Con listas de cualquier otro tipo (String, Producto…) el problema no existe, porque no hay ambigüedad posible.

Pregunta rápida

En una lista [10, 20, 30] de Integer, ¿qué hace lista.remove(5)?

Como 5 es un int, Java entiende "borra la posición 5", que no existe en una lista de 3 elementos. Si lo que querías era borrar el valor 5, la lista quedaría igual… pero el programa se cae antes.

2.4 Modificar la lista mientras la recorres

En esta sección

  • Provocas un ConcurrentModificationException y entiendes por qué ocurre.
  • Aprendes las dos formas correctas de eliminar mientras recorres.

Este código parece razonable y no lo es:

Borrado.java
ArrayList<String> palabras = new ArrayList<>();
palabras.add("sol");
palabras.add("luna");
palabras.add("mar");

for (String palabra : palabras) {
    if (palabra.equals("sol")) {
        palabras.remove(palabra);     // ¡FALLO!
    }
}

salida

Exception in thread "main" java.util.ConcurrentModificationException at java.base/java.util.ArrayList$Itr.checkForComodification(ArrayList.java:1104) at java.base/java.util.ArrayList$Itr.next(ArrayList.java:1058) at Borrado.main(Borrado.java:6)

Lo que pasa por dentro: un for-each no recorre la lista directamente, sino que le pide un iterador. La lista lleva un contador de cuántas veces la han modificado, y el iterador guarda una copia de ese número cuando nace. Al llamar palabras.remove(...) modificas la lista por fuera del iterador, los dos números dejan de coincidir, y en la siguiente vuelta el iterador se da cuenta y lanza la excepción.

Podría parecer exagerado, pero es una protección: si el iterador siguiera adelante, los elementos ya se habrían corrido de posición y se saltaría alguno en silencio. Java prefiere fallar de una vez y que lo arregles. Esto se llama comportamiento fail-fast.

El caso que no lanza excepción (peor todavía)

Si el elemento que borras es el penúltimo, el bucle termina sin error… y sin revisar el último. No se cae, simplemente hace mal el trabajo. Por eso no basta con "probar si no truena": hay que eliminar de la forma correcta.

Las dos formas correctas. La primera, un for hacia atrás:

for (int i = palabras.size() - 1; i >= 0; i--) {
    if (palabras.get(i).equals("sol")) {
        palabras.remove(i);
    }
}

Funciona porque no hay iterador, y porque al borrar la posición i solo se corren los elementos que ya revisaste. Si recorrieras hacia adelante, el siguiente elemento ocuparía la posición i y el i++ lo saltaría.

La segunda, removeIf, que dice directamente qué borrar:

palabras.removeIf(palabra -> palabra.equals("sol"));

La lista se encarga de recorrer y eliminar de forma segura, en una sola pasada. Es la forma moderna y la más corta; el for hacia atrás sirve para entender qué está pasando.

2.5 Listas de tus propios objetos

En esta sección

  • Buscas, filtras y calculas sobre listas de objetos que tú escribiste.
  • Entiendes por qué contains a veces dice que no, aunque el objeto "esté".

Aquí es donde la lista se pone útil de verdad. Los patrones son los mismos de la Parte 1, pero sin null de por medio y sin índices:

public static Producto buscarPorSku(ArrayList<Producto> inventario, String sku) {
    for (Producto producto : inventario) {
        if (producto.getSku().equals(sku)) {
            return producto;
        }
    }
    return null;
}

Compara este método con el equivalente sobre un arreglo: desapareció la comprobación de null (una lista no tiene casillas vacías) y desapareció el índice. Menos código, menos formas de equivocarse.

Ahora, la sorpresa de contains con objetos propios:

Contiene.java
ArrayList<Producto> inventario = new ArrayList<>();
inventario.add(new Producto("P01", "Teclado", 150000.0));

Producto buscado = new Producto("P01", "Teclado", 150000.0);   // otro objeto, mismos datos

System.out.println("¿La lista contiene un producto igual? " + inventario.contains(buscado));
System.out.println("¿Y el mismo objeto que agregamos? " + inventario.contains(inventario.get(0)));

salida

¿La lista contiene un producto igual? false ¿Y el mismo objeto que agregamos? true

contains compara con equals, y si tu clase no lo define, hereda el de Object, que compara identidad: "¿son exactamente el mismo objeto en memoria?". Dos productos con los mismos datos son objetos distintos, así que la respuesta es false. Lo mismo pasa con remove(objeto) y con indexOf.

Por eso, mientras tus clases no definan equals, busca comparando el campo que identifica al objeto (el SKU, la cédula, el ISBN) con un for, como en el método de arriba. Escribir equals correctamente es tema de la Parte 3.

2.6 Qué hace un ArrayList por dentro

En esta sección

  • Sabes que por dentro hay un arreglo, y qué pasa cuando se llena.
  • Distingues tamaño de capacidad.
  • Sabes cómo evitar redimensionamientos cuando conoces el tamaño de antemano.

No hay magia: por dentro, un ArrayList guarda sus elementos en un arreglo normal (Object[] elementData) y lleva un contador de cuántos hay. Igualito a tu agenda del ejercicio 1.10. Cuando el arreglo interno se llena, crea uno más grande, copia todo y descarta el viejo. La única diferencia con tu agenda es cuánto crece: la tuya duplicaba, y ArrayList crece 1.5 veces.

Conviene separar dos palabras que suenan parecido:

  • Tamaño (size()): cuántos elementos hay de verdad. Es lo único que tú ves.
  • Capacidad: cuántas casillas tiene el arreglo interno. No se ve desde fuera, y por eso el curso no te pide calcularla.

Una lista creada con new ArrayList<>() arranca con capacidad 10. Si le agregas 500 elementos, esto es lo que ocurre a tus espaldas:

AmpliaciónCapacidadElementos copiados
110 → 1510
215 → 2215
322 → 3322
………
10366 → 549366
Total10 ampliaciones, 1.084 copias

Suena caro, pero fíjate en el patrón: cada ampliación es más grande que la anterior, así que ocurren cada vez menos seguido. Repartido entre los 500 add, el costo promedio de agregar sigue siendo constante (se dice que add es O(1) amortizado). Aun así quedan dos desperdicios: el trabajo de copiar y las 49 casillas que sobran al final (549 para 500 elementos).

Si sabes de antemano más o menos cuántos elementos vas a meter, se lo dices al crear la lista y no hay ninguna ampliación:

ArrayList<Producto> carrito = new ArrayList<>(500);   // capacidad inicial, no tamaño

Ojo con ese número

new ArrayList<>(500) no crea 500 elementos: la lista sigue vacía y size() devuelve 0. Solo reserva el espacio por adelantado.

Pregunta rápida

¿Qué devuelve size() justo después de new ArrayList<>(100)?

Cero: la lista está vacía. El 100 es capacidad (casillas reservadas por dentro), no elementos. Confundir las dos cosas es el error clásico con este constructor.

2.7 List o ArrayList: programar hacia la interfaz

En código profesional vas a ver esta declaración mucho más que la que hemos usado:

List<Producto> inventario = new ArrayList<>();   // requiere import java.util.List;

List es una interfaz: dice qué se le puede pedir a una lista (add, get, remove, size…) pero no cómo se hace. ArrayList es una implementación: una de las formas de cumplir ese contrato, usando un arreglo por dentro. Hay otras, como LinkedList.

Declarar la variable como List y construirla como ArrayList significa "necesito una lista; hoy uso esta". Si mañana cambias de implementación, cambias una sola línea y el resto del programa sigue igual. Por eso los métodos que reciben listas se escriben así:

public static double valorTotal(List<Producto> productos) { ... }

Ese método acepta un ArrayList, un LinkedList o cualquier otra lista. Si lo declararas como ArrayList, estarías exigiendo una implementación concreta sin necesidad.

Cosas para recordar

  • import java.util.ArrayList; y new ArrayList<>().
  • Genéricos: ArrayList<Integer>, no ArrayList<int>.
  • size(), no length; get(i), no [i].
  • remove(int) borra por posición; remove(Object) por contenido.
  • Nunca elimines dentro de un for-each: usa removeIf o un for hacia atrás.
  • contains usa equals: con tus clases, compara el campo que identifica al objeto.
  • Declara List, construye ArrayList.
