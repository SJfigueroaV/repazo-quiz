Parte 1

Arreglos de objetos

Un arreglo de objetos no guarda objetos: guarda referencias a objetos, y arranca sin ninguna. Entender esa frase es la mitad de esta parte. La otra mitad es aprender a hacer a mano lo que después una lista hará por ti.

Al terminar esta parte

  • Sabes crear un arreglo, recorrerlo y consultar su tamaño.
  • Entiendes por qué un arreglo de objetos recién creado está lleno de null.
  • Reconoces y evitas el NullPointerException al recorrer un arreglo con huecos.
  • Sabes buscar, contar y promediar sobre un arreglo de objetos.
  • Puedes agregar y eliminar elementos a mano, manteniendo el arreglo compacto.
  • Puedes explicar por qué un arreglo estático no alcanza para un programa real.

1.1 El arreglo, en dos minutos

Un arreglo es una fila de casillas numeradas, todas del mismo tipo. Se le pide el tamaño al crearlo, y ese tamaño no cambia nunca. Las casillas empiezan con un valor por defecto: los arreglos de números empiezan en 0.

Repaso.java
int[] notas = new int[4];      // 4 casillas, todas en 0

System.out.println("Casillas: " + notas.length);
System.out.println("La casilla 0 vale: " + notas[0]);

notas[0] = 5;
notas[1] = 3;

for (int i = 0; i < notas.length; i++) {
    System.out.println("notas[" + i + "] = " + notas[i]);
}

salida

Casillas: 4 La casilla 0 vale: 0 notas[0] = 5 notas[1] = 3 notas[2] = 0 notas[3] = 0

Tres cosas que conviene tener claras desde ya:

  • El primer índice es 0 y el último es length - 1. Un arreglo de 4 casillas va de notas[0] a notas[3].
  • length se escribe sin paréntesis: es una propiedad del arreglo, no un método.
  • Si pides una casilla que no existe, el programa se cae con ArrayIndexOutOfBoundsException. Por eso el for siempre se escribe i < notas.length, nunca i <= notas.length.

Tres palabras parecidas que no son lo mismo

arreglo.length (un arreglo), texto.length() (un String) y lista.size() (una lista, la Parte 2). Misma idea, tres formas distintas de escribirla. Es de los errores más comunes al empezar.

Pregunta rápida

En int[] numeros = new int[5];, ¿cuál es el último índice válido?

El arreglo tiene 5 casillas, numeradas de 0 a 4. Pedir numeros[5] lanza ArrayIndexOutOfBoundsException. Y el tamaño no depende de cuántas casillas hayas usado: son 5 desde el momento en que lo creas.

1.2 Un arreglo de objetos nace vacío

En esta sección

  • Ves la diferencia entre un arreglo de números y un arreglo de objetos.
  • Entiendes que crear el arreglo y crear los objetos son dos pasos distintos.

Hasta aquí guardamos números. Cuando el arreglo es de objetos, cambia algo importante. Un int[] guarda los números dentro de sus casillas. Un Persona[] no guarda personas: guarda referencias, o sea direcciones que apuntan a objetos que viven en otra parte de la memoria. Y el valor por defecto de una referencia no es 0, es null: "no apunto a nada".

La comparación que se usa en clase: crear un arreglo de objetos es comprar un estante vacío. Tener el estante no significa tener los zapatos. Los compartimentos existen, pero están vacíos, y cada zapato hay que comprarlo por separado y ponerlo en su casilla.

Grupo.java
Persona[] grupo = new Persona[3];   // PASO 1: el estante de 3 casillas

System.out.println("Casillas del arreglo: " + grupo.length);
System.out.println("La casilla 0 vale: " + grupo[0]);

grupo[0] = new Persona("Ana", 20);      // PASO 2: cada objeto, uno por uno
grupo[1] = new Persona("Carlos", 22);

System.out.println("Ahora la casilla 0 vale: " + grupo[0]);
System.out.println("Pero la casilla 2 sigue valiendo: " + grupo[2]);

salida

Casillas del arreglo: 3 La casilla 0 vale: null Ahora la casilla 0 vale: Ana, 20 años Pero la casilla 2 sigue valiendo: null

Así se ve la memoria después del paso 1 y después del paso 2:

Después de: Persona[] grupo = new Persona[3]; grupo ---> [ null | null | null ] (¡todavía no existe ninguna Persona!) [0] [1] [2] Después de: grupo[0] = new Persona("Ana", 20); grupo[1] = new Persona("Carlos", 22); grupo ---> [ 0x01 | 0x02 | null ] | | v v +---------+ +------------+ | Persona | | Persona | | Ana, 20 | | Carlos, 22 | +---------+ +------------+

Dicho de otra forma: new Persona[3] reserva 3 casillas; new Persona(...) crea una persona. Son dos new distintos y hacen cosas distintas.

Pregunta rápida

Después de ejecutar Persona[] grupo = new Persona[3];, ¿cuántos objetos Persona existen en memoria?

Ninguno. Lo único que existe es el arreglo, con 3 casillas que valen null. Los objetos aparecen cuando escribes new Persona(...), una vez por cada uno.

1.3 La trampa del null

En esta sección

  • Provocas a propósito un NullPointerException y aprendes a leer su mensaje.
  • Aplicas la regla de oro para recorrer arreglos con huecos.

Si una casilla vale null y le pides un método, el programa se cae. Fíjate que la primera línea sí funciona y la segunda no:

Trampa.java
Persona[] grupo = new Persona[3];
grupo[0] = new Persona("Ana", 20);

System.out.println(grupo[0].getNombre());   // bien: la casilla 0 tiene una Persona
System.out.println(grupo[1].getNombre());   // ¡CRASH! la casilla 1 está vacía

salida

Ana Exception in thread "main" java.lang.NullPointerException: Cannot invoke "Persona.getNombre()" because "<local1>[1]" is null at Trampa.main(Trampa.java:5)

El mensaje es más amable de lo que parece; dice exactamente lo que pasó: no pude invocar Persona.getNombre() porque la casilla [1] es null. Y la última línea te dice el archivo y el número de línea. Cuando veas un NullPointerException, lee esas dos cosas antes que nada: qué método intentaste llamar y sobre qué cosa vacía.

Regla de oro

Siempre que recorras un arreglo de objetos que pueda tener casillas vacías, pregunta primero si la casilla tiene algo: if (grupo[i] != null). Esta comprobación es la que separa un programa que funciona de uno que se cae con datos reales.

El recorrido seguro se escribe de dos formas equivalentes. Con if:

for (int i = 0; i < grupo.length; i++) {
    if (grupo[i] != null) {
        System.out.println(grupo[i].getNombre());
    }
}

O saltándose las casillas vacías con continue, que evita anidar:

for (int i = 0; i < grupo.length; i++) {
    if (grupo[i] == null) {
        continue;            // esta casilla no me interesa, sigo con la próxima
    }
    System.out.println(grupo[i].getNombre());
}

Pregunta rápida

Con grupo[1] vacío, ¿cuál de estas dos líneas lanza NullPointerException?

Solo la segunda. Imprimir una referencia vacía es legal: println escribe el texto null y sigue. Lo que revienta es llamar a un método sobre algo que no existe. Por eso el null a veces se esconde: aparece impreso en la pantalla en vez de dar error, hasta que alguien le pide un método.

1.4 Buscar y calcular dentro de un arreglo de objetos

En esta sección

  • Aplicas el patrón de búsqueda: recorrer y devolver al encontrar.
  • Aplicas el patrón acumulador para contar y promediar.
  • Sabes por qué los textos se comparan con equals y no con ==.

Casi todo lo que harás con un arreglo de objetos es una variación de dos patrones. El primero es buscar: recorres, y en cuanto encuentras lo que querías, devuelves. Si el for termina sin encontrar nada, devuelves null.

public static Persona buscarPorNombre(Persona[] grupo, String nombre) {
    for (int i = 0; i < grupo.length; i++) {
        if (grupo[i] != null && grupo[i].getNombre().equals(nombre)) {
            return grupo[i];       // encontrada: salgo de una vez
        }
    }
    return null;                   // recorrí todo y no estaba
}

Fíjate en el orden de la condición: primero grupo[i] != null y después la comparación. Java evalúa el && de izquierda a derecha y se detiene en cuanto la primera parte es falsa, así que nunca llega a pedirle el nombre a una casilla vacía. Si inviertes el orden, el programa se cae.

Con textos, siempre equals

== pregunta "¿son el mismo objeto?" y equals pregunta "¿dicen lo mismo?". Dos Strings con el mismo contenido pueden ser objetos distintos, así que nombre == "Ana" a veces funciona y a veces no, lo cual es peor que si nunca funcionara. Usa equals.

El segundo patrón es el acumulador: una variable fuera del for que va creciendo mientras recorres. Aquí se usan dos, uno para sumar y otro para contar:

Estadisticas.java
Persona[] grupo = new Persona[4];
grupo[0] = new Persona("Ana", 20);
grupo[2] = new Persona("Carlos", 22);

int personas = 0;
int sumaEdades = 0;

for (int i = 0; i < grupo.length; i++) {
    if (grupo[i] == null) {
        continue;
    }
    System.out.println("[" + i + "] " + grupo[i]);
    personas++;
    sumaEdades += grupo[i].getEdad();
}

System.out.println("Personas registradas: " + personas);
System.out.println("Edad promedio: " + (double) sumaEdades / personas);

salida

[0] Ana, 20 años [2] Carlos, 22 años Personas registradas: 2 Edad promedio: 21.0

Dos detalles de ese promedio. El primero: se divide entre personas (las que existen de verdad), no entre grupo.length, porque las casillas vacías no deben bajar el promedio. El segundo: sin el (double), Java dividiría dos enteros y te daría 21 en lugar de 21.0; con 42 y 4 la diferencia sería entre 10.5 y 10, que ya es un error de verdad.

1.5 Agregar y eliminar a mano

En esta sección

  • Llevas la cuenta de cuántos elementos reales tiene un arreglo.
  • Eliminas un elemento sin dejar huecos, desplazando los siguientes.
  • Amplías un arreglo lleno copiándolo a uno más grande.

Un arreglo no sabe cuántos elementos "de verdad" tiene: solo sabe cuántas casillas existen. Si quieres una colección que crece y se encoge, tienes que llevar la cuenta tú, con un atributo que normalmente se llama cantidad. La regla del juego es: los elementos ocupan siempre las primeras cantidad casillas, sin huecos en la mitad. Con esa regla, agregar al final es fácil:

private Contacto[] contactos = new Contacto[10];
private int cantidad = 0;

public boolean agregar(Contacto contacto) {
    if (cantidad == contactos.length) {
        return false;              // no hay espacio
    }
    contactos[cantidad] = contacto;
    cantidad++;
    return true;
}

Eliminar cuesta más. Si borras el elemento de la posición 1 y lo dejas en null, rompes la regla: queda un hueco en la mitad. Para mantener el arreglo compacto hay que correr una posición a la izquierda todos los elementos que venían después (esto se llama shifting) y limpiar la última casilla:

public boolean eliminar(String nombre) {
    for (int i = 0; i < cantidad; i++) {
        if (contactos[i].getNombre().equals(nombre)) {

            for (int j = i; j < cantidad - 1; j++) {
                contactos[j] = contactos[j + 1];   // cada uno se corre un puesto
            }

            contactos[cantidad - 1] = null;        // limpio el duplicado del final
            cantidad--;
            return true;
        }
    }
    return false;
}

Nota que el recorrido va hasta cantidad y no hasta contactos.length: más allá de cantidad solo hay casillas vacías. Y como la regla garantiza que no hay huecos, dentro del for ya no hace falta preguntar por null.

Pregunta rápida

Una agenda compacta tiene 5 contactos en las posiciones 0 a 4. Eliminas el de la posición 2. ¿Cuántos contactos hay que mover?

Dos: los de las posiciones 3 y 4, que se corren a 2 y 3. Los de las posiciones 0 y 1 no se tocan. En el peor caso (eliminar el primero) hay que mover casi todos, y ahí está el costo: eliminar de un arreglo es lento cuando hay muchos elementos.

Queda el último problema: ¿y si el arreglo se llena? No se puede estirar, pero sí se puede reemplazar por uno más grande. Se crea un arreglo nuevo, se copian los elementos y se apunta la variable al nuevo. El viejo queda sin referencias y el recolector de basura lo limpia.

Ampliar.java
Persona[] grupo = new Persona[2];
grupo[0] = new Persona("Ana", 20);
grupo[1] = new Persona("Carlos", 22);

System.out.println("Capacidad antes: " + grupo.length);

grupo = Arrays.copyOf(grupo, grupo.length * 2);   // copia en uno del doble de tamaño
grupo[2] = new Persona("Diana", 25);

System.out.println("Capacidad después: " + grupo.length);
System.out.println(Arrays.toString(grupo));

salida

Capacidad antes: 2 Capacidad después: 4 [Ana, 20 años, Carlos, 22 años, Diana, 25 años, null]

Arrays.copyOf (de java.util.Arrays) hace el trabajo en una línea, pero por dentro no hay magia: crea el arreglo nuevo y copia una por una. En el ejercicio 1.10 lo vas a escribir a mano, porque ese bucle es justo el que hace una lista dinámica cuando se le acaba el espacio.

Lo que acabas de escribir tiene nombre

Un arreglo interno, un contador de cuántos elementos hay de verdad, y una ampliación automática al doble cuando se llena: eso es un arreglo dinámico. Es exactamente lo que hace ArrayList por dentro, y es de lo que trata la Parte 2. La diferencia es que ahí ya está escrito, probado y optimizado por otra gente.

1.6 Resumen de la Parte 1

Lo que cuesta cada operación en un arreglo, contando cuántos elementos hay que tocar:

OperaciónCómo se haceCosto
Leer o escribir por índicearreglo[i]Inmediato (O(1)): salta directo a la casilla
Saber el tamañoarreglo.lengthInmediato (O(1))
Buscar por contenidoRecorrer con un forO(n): en el peor caso, todo el arreglo
Agregar al finalarreglo[cantidad++] = xInmediato (O(1))… mientras quede espacio
Eliminar del medioShifting a la izquierdaO(n): hay que mover los siguientes
CrecerArreglo nuevo + copiar todoO(n): se copia elemento por elemento

Y los tres límites que te vas a topar en cualquier programa real:

  1. El tamaño es inmutable. Si reservaste 100 y llega el 101, el arreglo no puede crecer solo; te toca crear otro y copiar.
  2. Eliminar es costoso. O dejas huecos null (y validas en todas partes), o desplazas elementos a mano en cada borrado.
  3. Se desperdicia memoria. Si reservas 1.000 casillas para 10 elementos, el 99% de lo reservado no se usa.

Cosas para recordar

  • new Persona[3] crea casillas, no personas. Las casillas valen null.
  • Antes de llamar un método sobre una casilla, pregunta != null.
  • Imprimir null no falla; llamarle un método sí.
  • Los índices van de 0 a length - 1.
  • Los textos se comparan con equals, nunca con ==.
  • Si llevas un contador de elementos, recorre hasta cantidad, no hasta length.

En la Parte 2 dejamos de hacer este trabajo a mano: llega ArrayList, la lista que crece sola.
